## 개요
AWS re:Invent 2025의 키노트 세션은 **"Agents are changing the way we build, work, explore"**라는 메시지와 함께, 클라우드 컴퓨팅의 패러다임이 인프라를 넘어 **'업무(Work)의 추상화'**로 전환되고 있음을 선언했습니다. 본 포스팅에서는 키노트에서 발표된 AWS의 AI 비전과 전략, 그리고 이를 뒷받침하는 핵심 기술들을 상세히 정리합니다.

## 1. 패러다임의 변화: 결과의 추상화 (Outcome Abstraction)

### 인프라에서 업무로의 진화
AWS CEO 매트 가먼(Matt Garman)은 "클라우드가 기존에는 인프라를 추상화했다면, 이제 에이전트의 시대는 일(Work)을 추상화한다"는 강력한 메시지를 던졌습니다[1].
*   **과거:** 서버, 데이터베이스 등 복잡한 인프라 설계를 클라우드가 대신하는 '인프라 추상화' 단계.
*   **미래:** '어떻게(How)' 구현할지가 아니라, '무엇(What)'을 이룰 것인지 결과에 집중하는 **'결과의 추상화'** 단계[1].

### 르네상스 개발자 (Renaissance Developer)
AI가 코딩과 반복 업무를 대체함에 따라, 개발자의 역할은 **'르네상스 개발자'**로 재정의됩니다[2]. 예술과 과학을 넘나들던 르네상스 시대처럼, 이제 개발자는 단일 기술이 아닌 비즈니스와 시스템 전체를 아우르는 시야를 가져야 합니다.
*   **Role Shift:** 단순 코딩은 AI 에이전트에게 맡기고, 개발자는 전체 아키텍처 설계, 비즈니스 목표 부합 여부 판단, 보안 및 신뢰성 검증에 집중합니다[2].
*   **Ownership:** "The work is yours, not the tools." AI는 강력한 도구일 뿐, 결과에 대한 책임과 오너십은 여전히 사람에게 있습니다[2].

## 2. AWS AI 에이전트 풀스택 (Agent AI Full-stack)

AWS는 에이전트 시대를 위해 하드웨어부터 애플리케이션까지 연결된 **'AI 에이전트 풀스택'** 전략을 제시했습니다[3].

### Layer 1: SaaS Apps & Agents (완성형 애플리케이션)
별도의 모델이나 인프라 고민 없이 즉시 업무에 투입 가능한 영역입니다.
*   **Amazon Q:** 업무용 생성형 AI 어시스턴트.
*   **Amazon QuickSight:** 자연어 기반 데이터 시각화 도구.

### Layer 2: Frontier Agents (자율형 에이전트)
특정 도메인에서 자율적으로 판단하고 실행하는 고도로 전문화된 에이전트입니다[3].
*   **AWS DevOps Agent:** 장애 발생 시 로그와 메트릭을 분석하여 근본 원인을 찾고 해결책을 제안합니다.
*   **AWS Security Agent:** 코드 작성부터 배포까지 보안 취약점을 사전에 차단합니다.
*   **Kiro Autonomous Agent:** 개발자의 반복 작업을 백그라운드에서 병렬로 처리합니다[4].

### Layer 3: Custom Agent Build (개발 플랫폼)
**Amazon Bedrock**^1을 중심으로 사용자가 직접 에이전트를 개발하는 계층입니다.
*   **Agent Core Platform:** 수천~수백만 개의 에이전트를 안정적으로 운영하기 위한 오케스트레이션 레이어입니다[5].
*   **Intelligent Memory:** 에이전트가 대화 맥락을 유지하도록 단기(Session) 및 장기(User Preference) 메모리를 분리하여 관리합니다[4].
*   **Guardrails & Policy:** **AWS Cedar** 정책 언어를 기반으로 에이전트의 행동을 실시간으로 모니터링하고 통제하여 안전성을 확보합니다[4].

### Layer 4: Infrastructure (기반 인프라)
에이전트를 대규모로, 비용 효율적으로 운영하기 위한 하드웨어 기반입니다.
*   **AWS Trainium 3:** 대규모 모델 학습 비용을 최대 50% 절감하고 성능을 4.4배 향상시킨 차세대 칩셋[6].
*   **NVIDIA GB200 (Project Ceiba):** 자율 에이전트 및 초거대 AI 모델을 위한 고성능 컴퓨팅 인스턴스[7].

## 3. 차세대 파운데이션 모델: Amazon Nova

AWS는 자체 개발한 고성능 모델 라인업인 **Amazon Nova**를 공개하며 모델 선택의 폭을 넓혔습니다. Nova 모델은 **Amazon Bedrock**을 통해 제공됩니다.

### Nova 2 라인업
*   **Nova 2 Lite:** 비용 효율적인 경량 모델로, 빠른 응답 속도가 필요한 작업에 적합[8].
*   **Nova 2 Pro:** 복잡한 추론과 의사결정이 필요한 작업을 위한 고지능 모델[8].
*   **Nova 2 Omni:** 텍스트, 이미지, 비디오 등 멀티모달 입출력을 지원하는 통합 모델[8].
*   **Nova 2 Sonic:** 음성 대화(Speech-to-Speech)에 특화된 모델로, **한국어 음성 입출력을 완벽하게 지원**하여 자연스러운 실시간 대화가 가능합니다[8], [9].

### Nova Act & Forge
*   **Nova Act:** 단순 추론을 넘어, AWS 워크플로우 안에서 실제 액션(Action)을 수행하는 에이전트 모델[10].
*   **Nova Forge:** 기업이 자체 데이터로 모델을 미세 조정(Fine-tuning)하고 커스터마이징할 수 있는 플랫폼[10].

## 4. 인프라의 진화: 워크로드별 최적화

AI와 게임 워크로드를 위한 컴퓨팅 인프라 업데이트도 발표되었습니다. 게임 서버의 성능은 곧 플레이어의 경험(Latency, Lag)과 직결되므로 워크로드 특성에 맞는 인스턴스 선택이 중요합니다[8].

| 인스턴스 | 프로세서 | 특징 및 타겟 워크로드 |
| :--- | :--- | :--- |
| **EC2 H2a** | AMD EPYC | 최대 192 vCPU, 대규모 동시 접속(MMORPG) 처리에 최적화. 가성비 19% 향상[6]. |
| **EC2 M8h** (Preview) | High Clock | 밀리초(ms) 단위 반응성이 필수인 FPS/액션 게임 서버용[6]. |
| **EC2 C7i** (Preview) | Intel Xeon | 매치메이킹, 세션 관리 등 고대역폭 네트워크가 필요한 서비스[6]. |
| **Graviton 5 (M9g)** | ARM-based | 이전 세대 대비 25% 이상 성능 향상, DB 및 웹 앱의 가성비 극대화[7]. |

## 5. 결론: 속도와 안전성의 균형

이번 키노트의 핵심은 AI 도입 자체가 아니라, **'얼마나 빠르고 안전하게 실행하느냐(Velocity & Safety)'**에 있습니다[11]. 스펙 기반(Spec-driven) 개발로 방향을 명확히 하고, AI를 통해 자동화된 판단과 테스트를 수행함으로써 기업은 기술적 실험 단계를 넘어 비즈니스 경쟁력을 확보해야 합니다.
