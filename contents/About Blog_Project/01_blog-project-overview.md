## 개요

이 글은 **외부 프레임워크 없이(Vanilla JS)** 직접 구현한 개인 블로그 프로젝트의 첫 번째 기록이다.  
이 블로그는 단순한 결과물 전시용 포트폴리오가 아니라,  
**공부한 내용, 직접 만든 것, 흥미를 가지고 파고든 주제들을 장기적으로 기록하기 위한 공간**을 목표로 만들어졌다.

완성도보다 **과정**, 정답보다 **고민의 흔적**을 남기는 것이 이 블로그의 핵심 방향이다.

## 왜 블로그를 직접 만들었는가

기존의 블로그 플랫폼이나 프레임워크를 사용하지 않고  
굳이 처음부터 직접 구현한 이유는 단순하다.

- “글을 쓰는 공간”이 아니라 **구조를 이해할 수 있는 시스템**을 만들고 싶었다
- 프론트엔드·배포·데이터 흐름까지 **전체를 통제 가능한 구조**로 구성하고 싶었다
- 나중에 다시 봤을 때  
  *“아, 이때 이런 고민을 했구나”* 를 그대로 확인할 수 있는 기록이 필요했다

즉, 이 블로그는 결과물이 아니라 **학습 로그이자 프로젝트 기록장**이다.

---

## 프로젝트의 성격

이 프로젝트는 다음과 같은 성격을 가진다.

- ❌ 최신 프레임워크 비교 / 트렌드 소개용 블로그 아님
- ❌ 정제된 튜토리얼 위주의 기술 블로그 아님
- ✅ 직접 만들고 부딪힌 과정 중심
- ✅ 시행착오와 설계 선택 이유를 그대로 기록
- ✅ 나중에 다시 봐도 이해 가능한 구조 설명

## 기술적 방향성 요약

### 1. 프레임워크 미사용

React, Vue, Svelte 등의 프레임워크를 사용하지 않고  
**HTML / CSS / JavaScript만으로 SPA 구조를 직접 구현**했다.

이 선택의 목적은 성능이나 생산성을 극대화하기 위함이 아니다.  
이 블로그는 **정적 웹 기반 포스팅**이라는 특성을 가지며,  
그에 가장 적합한 구조와 운영 전략을 선택한 결과이다.

- 정적 파일 중심의 구조가 배포·운영 측면에서 단순하고 안정적이며
- 서버 의존성을 최소화할 수 있고
- 콘텐츠 중심의 블로그 특성상 CSR 기반 구조가 충분히 효과적이라고 판단했다

즉, 프레임워크를 배제한 이유는 실험이나 학습 자체가 목적이기보다는  
**블로그라는 서비스 성격에 맞는 합리적인 구조 선택**에 가깝다.

---

### 2. Client-Side Rendering 기반 SPA

- 단일 진입점(`index.html`)
- History API 기반 라우팅
- 페이지별 JS 모듈 동적 로딩
- Markdown 기반 콘텐츠 렌더링

즉, **백엔드 템플릿 엔진 없이 동작하는 순수 CSR 구조**다.

---

### 3. 콘텐츠와 코드의 분리

블로그의 글은 프론트엔드 코드와 분리되어 관리된다.

- 글은 Markdown 파일로 작성
- 별도의 저장소 및 DB에 저장
- 프론트엔드는 오직 “보여주는 역할”만 담당

이 구조를 통해,

- 글 작성 ↔ UI 개발을 독립적으로 진행 가능
- UI 변경 없이도 콘텐츠 확장 가능
- Headless CMS에 가까운 형태를 유지할 수 있다

## 이 블로그에서 다룰 내용들

앞으로 이 **Blog Project** 카테고리에서는 다음과 같은 내용을 다룬다.

- 블로그 전체 아키텍처 설계
- SPA 라우터 구현 방식
- Markdown 렌더링 구조
- UI/UX 설계 고민

- SEO, 검색, 모바일 최적화 등 개선 과정

완성된 결과가 아니라,  
**“어떻게 만들어졌는지”를 중심으로 기록**할 예정이다.
