## 개요

이 글은 **Blog Project** 시리즈의 세 번째 기록으로,  
이 블로그에서 **Markdown 콘텐츠를 어떻게 렌더링하고, 읽기 좋은 UI로 표현했는지**를 중심으로 정리한다.

블로그의 본질은 “기능”보다 **가독성**과 **맥락 유지**에 있다고 생각했다.  
그래서 렌더링 파이프라인과 스타일링 모두를  
“글을 오래 읽어도 피로하지 않은가?”라는 기준으로 설계했다.

## 왜 Markdown인가

콘텐츠 작성 포맷으로 Markdown을 선택한 이유는 명확하다.

- 작성 속도가 빠르고 문법이 단순함
- 코드 블록, 인용, 리스트 표현이 자연스러움
- Git 기반 관리에 최적화됨
- 장기적으로 봤을 때 **도구 종속성이 낮음**

이 블로그의 글은  
“지금의 나”뿐 아니라 **나중의 나**가 다시 읽을 가능성이 높기 때문에,  
특정 에디터나 플랫폼에 묶이지 않는 포맷이 중요했다.

---

## Markdown → HTML 렌더링 흐름

렌더링의 전체 흐름은 다음과 같다.

1. Page 모듈이 게시글 데이터를 요청
2. DB 또는 API에서 Markdown 본문을 문자열로 수신
3. Markdown 파서를 통해 HTML로 변환
4. 변환된 HTML을 `#main-content` 영역에 주입
5. 코드 블록에 대해 문법 강조 처리

이 구조의 핵심은 **렌더링 책임을 Page 레벨에서 명확히 분리**한 것이다.

- 라우터는 렌더링에 관여하지 않음
- Page는 “어떤 콘텐츠를 어떻게 보여줄지”만 책임
- UI 스타일은 전부 CSS로 통제

## 코드 블록 디자인 방향

기술 블로그에서 코드 블록은 **가장 중요한 시각 요소** 중 하나다.  
그래서 기본적인 사각형 박스 대신,  
**macOS 터미널/에디터 창과 유사한 UI**를 적용했다.

디자인 목표는 다음과 같았다.

- 코드와 본문이 시각적으로 명확히 구분될 것
- 너무 튀지 않되, 스크롤 중 자연스럽게 시선을 끌 것
- 긴 코드도 읽기 부담 없을 것

이를 위해,

- 상단에 창 형태의 헤더 영역 추가
- 좌측 정렬, 충분한 패딩
- 배경 대비를 낮춰 눈의 피로 감소

과한 디자인보다는 **“익숙함”**에 초점을 맞췄다.

---

## 문법 강조(Syntax Highlighting)

코드 가독성을 위해 문법 강조를 적용했다.

중요하게 본 포인트는 다음이다.

- 언어별 색상이 과하지 않을 것
- 배경과 대비가 자연스러울 것
- 다크/라이트 테마 전환 시에도 유지될 것

문법 강조는 **보조 수단**이지,  
콘텐츠 자체보다 앞서면 안 된다고 생각했다.

---

## 인용문과 본문 가독성

Markdown의 인용문(`blockquote`)은  
자칫하면 본문 흐름을 끊거나, 너무 튀어 보이기 쉽다.

그래서 인용문은 다음 기준으로 스타일링했다.

- 본문보다 한 단계 낮은 시각적 강조
- 좌측 라인과 배경색으로만 구분
- 긴 인용도 부담 없이 읽히도록 여백 확보

이 블로그에서는 인용문을  
“강조”가 아니라 **맥락 보조**로 사용한다는 전제를 두었다.

## 전체 UI 설계 기준

UI 설계에서 가장 우선한 기준은 하나다.

> **사용자가 ‘글’에 집중할 수 있는가**

그래서 다음 요소들을 의도적으로 배제했다.

- 불필요한 애니메이션
- 과도한 색상 사용
- UI 요소 간 경쟁적인 시각 효과

대신,

- 충분한 행간
- 안정적인 폰트 크기
- 예측 가능한 레이아웃

을 유지하는 쪽을 선택했다.

---

## “에디터 감성”을 선택한 이유

블로그 전체 UI는  
웹 서비스라기보다는 **코드 에디터 / 문서 뷰어**에 가깝다.

이 선택의 이유는 단순하다.

- 이 블로그의 주요 독자는 결국 “나”
- 글을 쓰고, 읽고, 다시 수정할 가능성이 높음
- 익숙한 개발 환경의 감성이 가장 편함

그래서 화려한 블로그 테마보다는,  
**조용한 작업 공간 같은 UI**를 지향했다.

## 이 구조의 한계

물론 현재 구조에도 한계는 있다.

- 모바일 환경에서는 여전히 개선 여지가 있음
- 긴 글에서 목차/탐색 보조 기능이 부족함
- 검색 기능 부재

이 부분은 이후 글에서  
**모바일 최적화, UX 개선, 검색 기능**으로 이어서 정리할 예정이다.
