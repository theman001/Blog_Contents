## 개요

이 글은 **Blog Project** 시리즈의 마지막 글로,  
지금까지 정리한 구조와 구현을 바탕으로 한 **회고(Retrospective)** 와  
앞으로 이 블로그를 어떻게 발전시켜 나갈 것인지에 대한 **향후 계획**을 기록한다.

이 프로젝트는 처음부터 “완성형 서비스”를 목표로 하지 않았다.  
대신, **지속적으로 손보고 바꿀 수 있는 기록 공간**을 만드는 것이 목적이었다.

따라서 이 글에서 정리한 향후 계획 역시  
일회성 결론이 아니라,  
**실제 개선 과정과 시행착오를 이후 포스팅을 통해 계속 기록해 나갈 예정**이다.

---

## 지금 구조에 대한 총평

현재 블로그의 구조는 다음과 같은 특징을 가진다.

- 정적 웹 기반 SPA 구조
- 프론트엔드와 콘텐츠 완전 분리
- 서버 운영 부담이 거의 없는 배포 방식
- Markdown 중심의 글 작성 흐름

이 구조는 **블로그라는 용도에 과하지도, 부족하지도 않다**고 느낀다.

특히 만족스러운 부분은:

- 글을 쓰는 행위가 구조 변경으로 이어지지 않는 점
- UI나 배포 방식을 바꿔도 콘텐츠는 그대로 유지된다는 점
- “관리”보다 “기록”에 집중할 수 있다는 점이다

---

## 아쉬운 점과 한계

반대로, 실제로 사용하면서 체감한 한계도 분명하다.

- 모바일 환경에서의 가독성 부족
- 긴 글에서 탐색 보조 수단이 부족함
- 검색 기능 부재
- CSR 구조 특성상 SEO 대응이 기본적으로 약함

이 한계들은 구조적 결함이라기보다는,  
**아직 구현하지 않은 영역**에 가깝다.

---

## 향후 개선 방향

앞으로의 개선은 기능 추가보다  
**사용자 경험(UX)을 우선**으로 두고 진행할 계획이다.

### 1. 모바일 최적화 UI 도입

- 모바일 화면에서의 행간, 폰트 크기 재조정
- 코드 블록 스크롤 UX 개선
- 터치 환경에서의 조작 불편 요소 제거

“모바일에서도 읽을 수 있는 블로그”가 아니라,  
**“모바일에서도 편하게 읽히는 블로그”**를 목표로 한다.

---

### 2. 전체적인 UI/UX 개선

UI 개선의 방향은 명확하다.

- 더 화려하게 ❌
- 더 직관적으로 ✅

구체적으로는:

- 페이지 이동 흐름 단순화
- 불필요한 시각 요소 제거
- 글 읽기 흐름을 방해하는 요소 최소화

기능보다 **경험을 우선시하는 개선**을 지속할 예정이다.

---

### 3. SEO 구축 전략

CSR 기반 구조의 한계를 인지하고 있기 때문에,  
SEO는 “무시”가 아니라 **의도적으로 대응**할 계획이다.

- 메타데이터 구조 정비
- URL 구조 정돈
- 검색 엔진 친화적인 콘텐츠 구조 설계

완벽한 SEO를 목표로 하기보다는,  
**정적 블로그로서 할 수 있는 선까지**를 목표로 한다.

---

### 4. 게시글 검색 기능 추가

글이 쌓일수록 검색은 필수가 된다.

- 클라이언트 사이드 검색
- 제목, 태그, 본문 기준 탐색
- 빠르고 단순한 UX 중심 구현

이 기능은  
“기능 추가”라기보다는 **기록을 다시 찾기 위한 도구**에 가깝다.

---

### 5. 이미지 첨부 및 자산 관리 방식 개선

이 블로그는 Markdown 기반으로 관리되는 정적 웹 구조이기 때문에,  
이미지 파일을 게시글과 함께 관리하는 데 제약이 있다.

- Markdown 파일은 DB에 동기화되는 구조
- Git 레포지토리에 이미지를 함께 두기에는 관리와 배포가 번거로움
- 정적 호스팅 환경에서 이미지 경로 관리가 복잡해질 수 있음

이를 해결하기 위한 방안으로 **Cloudflare R2**를 이미지 저장소로 사용하는 구조를 고려하고 있다.

#### 이미지 관리 전략 개요

이 블로그는 Markdown 기반으로 게시글을 관리하는 구조이기 때문에,  
이미지 파일을 게시글과 함께 다루는 방식에 대한 별도의 전략이 필요하다.

- 게시글 본문(`.md`)은 DB에 동기화되는 텍스트 중심 구조
- 이미지 파일까지 DB나 프론트엔드 코드에 포함시키기에는 관리 부담이 큼
- 정적 웹 환경에서는 이미지 제공을 위한 별도의 자산 관리 방식이 필요함

이를 해결하기 위해,  
**Git을 원본 저장소(Source of Truth)로 유지하면서  
Cloudflare R2를 이미지 서빙용 스토리지로 사용하는 구조**를 고려하고 있다.

이미지 관리의 기본 원칙은 다음과 같다.

- 게시글 본문과 이미지 모두 **Git에서 함께 관리**
- 서비스 제공 시에는 이미지 파일만 **Cloudflare R2로 동기화**
- 실제 웹 페이지에서는 R2에 저장된 이미지를 기준으로 로드

구체적인 흐름은 다음과 같다.

1. 이미지 파일을 게시글과 함께 Git 레포지토리에 커밋
2. 동기화 스크립트를 통해 이미지 파일을 Cloudflare R2로 업로드
3. 업로드된 이미지의 R2 경로를 기준으로:
   - key: 게시글 또는 논리적 식별자
   - value: R2에 저장된 이미지 파일 경로(URL)
4. 게시글 렌더링 시,  
   Markdown 본문에서 해당 경로를 참조하여 이미지를 표시

이 구조를 통해,

- Markdown 파일은 텍스트 중심으로 단순하게 유지하고
- 이미지와 같은 정적 자산은 전용 스토리지에 위임하며
- Git 기반의 이력 관리와 CDN 기반의 빠른 이미지 제공을 동시에 확보할 수 있다

이미지 첨부 기능은  
처음부터 필수로 구현하기보다는,  
**필요해질 때 자연스럽게 확장 가능한 구조**로 두는 것을 목표로 한다.

---

## 이 프로젝트를 통해 얻은 것

이 블로그 프로젝트를 통해 얻은 가장 큰 수확은  
특정 기술 스택이 아니라 **구조에 대한 감각**이다.

- 어떤 부분을 단순하게 유지해야 하는지
- 어디를 분리해야 나중에 편해지는지
- 블로그라는 서비스에 정말 필요한 것이 무엇인지

이 감각은,  
앞으로 다른 프로젝트를 하더라도 계속 활용될 것이다.

---

## 마무리

이 시리즈는 여기까지지만,  
블로그 프로젝트 자체는 이제부터가 시작이다.

구조는 필요에 따라 바뀔 수도 있고,  
글은 생각날 때마다 조금씩 쌓일 것이고,  
잘된 것뿐 아니라 시행착오도 그대로 남길 예정이다.

이 블로그는  완성된 결과를 보여주기보다는,  
**만들어 가는 과정을 기록하는 공간**이기 때문이다.
