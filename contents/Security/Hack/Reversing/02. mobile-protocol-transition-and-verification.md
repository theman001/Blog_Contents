## 1. 개요

본 보고서는 `KakaoWebTalk` 프로젝트의 핵심 과제인 **로그인 프로토콜 역공학** 과정에서의 전략 전환과 그 검증 결과를 정리한 문서이다.  
초기에는 PC 클라이언트(`KakaoTalk.exe`)의 메모리 덤프를 통해 인증 데이터를 확보했으나, PC 전용 프로토콜의 복잡성과 폐쇄성으로 인해 **모바일(Android) API 위장 전략**으로 방향을 전환하였다.

---

## 2. 데이터 획득: 메모리 스캔 (Frida)

### 2.1 스캔 기법
Themida로 보호된 PC 클라이언트의 암호화 로직을 우회하기 위해, 네트워크 전송 직전(`send`) 시점의 힙 메모리를 스캔하는 `hook_scan_v2.js`를 개발·활용하였다.

### 2.2 획득 데이터 (Key Artifacts)
메모리 덤프에서 `application/x-www-form-urlencoded` 형식의 로그인 페이로드를 확인하였다.

`email=theman****%40gmail.com  
&password=********  
&device_uuid=supnx3Mu0HpG9brcqZukaAaPxkbBRuSe7WkG1lYzDDyaawfIrMjtA5dlI0Loeb+dBm/9CJmmCzDOqs4fdiIog==  
&os_version=10.0  
&client_version=3.4.0.0`

- **device_uuid**: PC 버전에 등록된 기기 고유 식별자(Base64). 서버가 “인증된 PC”임을 판단하는 핵심 키.

---

## 3. 프로토콜 분석 및 검증 (Trial & Error)

### 3.1 실험 1: PC 프로토콜 직접 모방 (실패)
- **시도**: 추출한 `device_uuid`와 페이로드를 사용하여 PC 인증 서버(`talk-pilsner.kakao.com`)에 HTTP POST 요청 전송
- **결과**: `404 Not Found`
- **분석**: PC 클라이언트는 표준 HTTP가 아닌 **LOCO 바이너리 프로토콜**을 사용하며, 메모리에서 확인한 문자열은 내부 구조체에 불과함

### 3.2 실험 2: 모바일 API에 PC 데이터 전송 (부분 실패)
- **시도**: 안드로이드 인증 서버(`katalk.kakao.com`)에 PC 인증 데이터 전송
- **결과**
  - `status: -999` → 앱 버전 너무 낮음
  - 버전 상향 후 `status: -500`
- **분석**: 모바일 서버는 PC 형식의 `device_uuid`, `User-Agent`를 허용하지 않음

## 4. 최종 전략: 안드로이드 앱 위장 (Hybrid Device Spoofing)

### 4.1 전략 개념
PC 프로토콜을 완전히 배제하고, 표준 HTTPS 기반의 **안드로이드 API**를 사용한다.  
계정 정보는 재사용하되, **기기 식별자는 새 안드로이드 기기로 생성**한다.

### 4.2 구현 로직
1. **클라이언트 위장**
   - `User-Agent`: `KT/25.7.2 An/14 ko`
   - Header `A`: `android/25.7.2/ko`
2. **기기 식별자**
   - `device_uuid`: Android ID 기반 SHA-1 해시 (PC UUID 미사용)
3. **로그인 흐름**
   1. 웹에서 계정 정보 입력
   2. `/android/account/login.json` 요청
   3. `status: -100` 수신
   4. 인증번호 요청 → 사용자 입력
   5. 기기 등록 완료 및 토큰 발급

## 5. Wear OS APK 분석 (v25.7.0)

### 5.1 인증 구조
Wear OS 버전은 **단독 로그인 불가**한 컴패니언 앱으로, 휴대폰에서 전달된 토큰을 사용한다.

- 수신 객체: `AuthItem`
- 포함 값: `id`, `token`, `uuid`

### 5.2 네트워크 인터셉터 분석
- `BreweryInterceptor`: `Authorization: <token>-<uuid>`
- `RequestHeaderInterceptor`: `Authorization`, `duuid`
- `NodeInterceptor`: 화면·밀도 정보

### 5.3 미포함 요소
- `X-VC` 생성 로직 없음
- `libtalkand_aes.so` 없음
- `login.json` 엔드포인트 없음

## 6. 안드로이드 로그인 프로토콜 검증

### 6.1 핵심 엔드포인트
- `/android/account/login.json`
- Content-Type: `application/x-www-form-urlencoded`

### 6.2 필수 헤더 요약
- **X-VC**  
  `SHA512("BARD|{device_info}|DANTE|{email}|SIAN")[0:16]`
- **User-Agent**: `KT/{version} An/{os_ver} {lang}`
- **Header A**: `android/{version}/{lang}`
- **Device-Info**: android SDK, uuid, model, resolution 등

### 6.3 검증 결과
- `status: 30` → 비밀번호 오류
- `status: -100` → 기기 미등록 (정상 흐름 확인)
- `serverTime` 반환 확인

---

## 7. -500 오류 디버깅 로그 요약

다수의 실험 결과, 오류 원인은 **네트워크·SIM 정보가 아닌 헤더 검증/X-VC/파라미터 정합성**으로 판단된다.

주요 가설:
- X-VC 알고리즘 버전 차이
- OkHttp 특유의 헤더/압축 파이프라인 요구
- `adid_enabled`, `permanent` 플래그 누락
