## 🥇 1순위 (발생 확률 ★★★★★)  
### WsusPool Application Pool Identity 설정 오류

### 🔍 의심 근거
- WSUS Runtime Error 발생
- `ReportingWebService.asmx` 접근 불가
- 클라이언트 보고 실패
- WSUS 콘솔 오류 동반

### ❗ 문제 요약
- `WsusPool` Identity가 **NetworkService**로 설정됨
- Microsoft 권장 설정은 **ApplicationPoolIdentity**

### ✅ 해결 방법
1. IIS 관리자 실행
2. Application Pools → `WsusPool`
3. Advanced Settings → Identity
4. `ApplicationPoolIdentity`로 변경
5. IIS 재시작 (`iisreset`)

### 📌 비고
- 실무에서 **가장 빈번한 WSUS 장애 원인**
- 권한·WebService·Reporting 문제를 동시에 유발

## 🥈 2순위 (발생 확률 ★★★★☆)  
### WSUS 클라이언트 등록 트리거 오해 (로그인/재부팅)

### 🔍 의심 근거
- GPO는 적용되었으나 WSUS에 PC 미등록
- PC가 켜져 있으나 로그인 안 된 상태 다수

### ❗ 문제 요약
- WSUS 등록은 **GPO 적용과 별개**
- 등록 트리거는:
  - 로그인
  - 재부팅
  - Windows Update Scan 수행

### ✅ 해결 방법
- 테스트 PC에서 다음 순서 실행
`
usoclient StartScan
usoclient ReportNow
`
- 또는 재부팅 후 로그인 상태 유지

### 📌 비고
- “PC 켜져 있음 = WSUS 등록”은 **잘못된 인식**

---

## 🥉 3순위 (발생 확률 ★★★☆☆)  
### IIS WebService / Reporting 서비스 비정상

### 🔍 의심 근거
- 특정 WSUS WebService URL 접근 실패
- 콘솔 일부 기능만 오류 발생

### ❗ 문제 요약
- WSUS는 **IIS WebService 의존도가 매우 높음**
- Application Pool은 살아 있으나 내부 오류 발생 가능

### ✅ 해결 방법
- IIS 상태 점검
- WsusPool Started 여부 확인
- `ReportingWebService.asmx` 직접 접근 테스트
- IIS 로그 및 Application 이벤트 로그 확인

---

## 4️⃣ 4순위 (발생 확률 ★★☆☆☆)  
### Dual Scan 설정 오해 또는 정책 미적용

### 🔍 의심 근거
- 일부 요청이 Microsoft Update로 향함
- WSUS 정책 적용 후에도 혼합 동작

### ❗ 문제 요약
- Dual Scan 자체보다 **WSUS 서버 장애로 인한 우회 동작** 가능성 높음

### ✅ 해결 방법
- GPO에서 Dual Scan 비활성화 확인
- `gpresult /r`로 정책 적용 여부 확인
- 서버 정상화 후 재확인

### 📌 비고
- 실제 원인일 확률은 낮음
- 서버 장애 시 **결과적으로 Dual Scan처럼 보일 수 있음**

---

## 5️⃣ 5순위 (발생 확률 ★☆☆☆☆)  
### WSUS DB 또는 콘텐츠 폴더 권한 문제

### 🔍 의심 근거
- 장기 미점검 서버
- 디스크 정리·권한 변경 이력 존재

### ❗ 문제 요약
- WSUS Content, DB 접근 실패 시 비정상 동작 가능

### ✅ 해결 방법
- WSUS Content 폴더 권한 확인
- SQL/WID 서비스 상태 확인
- 이벤트 로그에서 DB 관련 오류 검색

## 결론

WSUS 장애 분석 시 가장 중요한 접근 방식은 다음 순서이다.

1. **IIS / Application Pool Identity부터 확인**
2. 클라이언트가 “정상적으로 등록될 수 있는 조건”인지 검증
3. Dual Scan은 **가장 마지막에 의심**

> WSUS 문제의 70% 이상은  
> **서버 설정(IIS) + 등록 트리거 오해**에서 발생한다.
